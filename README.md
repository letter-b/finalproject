# Retail Rental Analytics System

> Can unsold electronics generate more revenue as rentals than as clearance markdowns?  
> This project builds the data infrastructure, analysis, and dashboards to answer that question.

---

## The Idea

Every year, retailers discount billions of euros worth of unsold electronics — TVs, laptops, drones, consoles — by 40 to 75% just to clear shelf space. The product loses most of its value. The customer gets a deal. The retailer takes a loss. And eventually, the item ends up as e-waste.

This project proposes an alternative: instead of discounting, enrol items that have been unsold for 12+ months into a rental programme. The data suggests rental beats markdown in roughly 60% of cases, with a median revenue ratio of 1.40× after operational costs — and across 10,000 Monte Carlo simulations, rental never lost overall.

The model is intentionally honest. Operational costs (15–28%), no-return rates, damage write-offs, and downtime between rentals are all accounted for. The real-world ceiling is 40–55% win rate. The optimistic headline is a starting point for a conversation, not a guarantee.

## Notebooks

### 01 · Data Generation
Generates the full MySQL database from scratch. Produces all CSVs to `data/generated_data/` and flat files to `data/tableau/`. Run this first. Do not modify unless regenerating the dataset.

### 01B · Data Generation (Re-run)
Re-runs the pipeline with updated parameters. Use this to simulate a new data batch for the live demo.

### 02 · EDA
11 sections of exploratory analysis. Key findings:
- Repeat renters (30% of customers) drive 50% of revenue
- Rental duration splits cleanly by product type
- The €300–600 price tier drives total revenue volume; €1000+ wins per transaction

### 03 · A/B Testing
Formal hypothesis test comparing rental revenue vs markdown revenue. Tests whether the observed win rate is statistically significant or could be explained by chance.

### 04 · Machine Learning
Three models plus stress testing:
- **Model 1 — Random Forest:** predicts whether a product will be more profitable via rental before it enters the programme
- **Model 2 — Linear Regression:** projects monthly rental revenue forward 6 months
- **Model 3 — Logistic Regression:** predicts customer churn risk (late returns / no-returns)
- **Section 4a — Sensitivity Analysis:** tests the thesis under optimistic, realistic, and pessimistic cost assumptions
- **Section 4b — Monte Carlo:** 10,000 simulations varying all uncertain inputs simultaneously

### live_feed
Inserts 15 rental records per batch into MySQL. Used for the live demo — run during the presentation, then refresh Power BI to show the dashboard updating in real time.

## How the Data Pipeline Works

This project doesn't use manual CSV imports. Everything from data generation to dashboard is automated through a single pipeline.

**The two key libraries:**
- `pymysql` — opens the physical connection between Python and MySQL
- `SQLAlchemy` — translates pandas DataFrames into SQL automatically

**The flow:**

```
Python generates data
  → pandas DataFrames
    → SQLAlchemy + pymysql
      → MySQL tables (written automatically)
        → Views created on top of tables
          → Power BI reads views live
```

Running `01_data_generation.ipynb` from top to bottom rebuilds the entire database from scratch in under a minute. No Workbench. No manual imports.

**Writing a table is one line:**
```python
df.to_sql("products", con=engine, if_exists="replace", index=False)
```

**The live feed** (`live_feed.ipynb`) takes it further — it inserts 15 new rental records every 30 seconds directly into MySQL using `if_exists="append"`. Power BI picks them up on refresh. This is the live demo moment.

**To run the live feed without a notebook:**
```bash
jupyter nbconvert --to script notebooks/live_feed.ipynb
python notebooks/live_feed.py
```

This pattern is a standard ETL pipeline (Extract, Transform, Load) — the same architecture used in production data engineering, just at a smaller scale.

**Further reading:**
- [`pandas.DataFrame.to_sql()`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.to_sql.html) — the method that writes DataFrames to SQL tables automatically, inferring schema from the DataFrame itself
- [`SQLAlchemy create_engine()`](https://docs.sqlalchemy.org/en/20/core/engines.html) — the connection string that connects Python to MySQL (or any other database by swapping the dialect)

## Business Context

This project was built as a final project for the Ironhack Data Analytics bootcamp (April 2026). The dataset is fully synthetic but calibrated against real-world benchmarks:

- Markdown ranges (40–75%) reflect published retail industry data (NRF, 2024–2025)
- Operational cost ranges (15–28%) reflect consumer electronics rental market reports
- No-return and damage rates (4–8%) reflect industry standards for electronics rental
- The 12-month eligibility threshold represents one full retail sales cycle

The model is intentionally optimistic as a proof of concept. A production version would incorporate real retailer data, category-specific thresholds, and dynamic pricing.
